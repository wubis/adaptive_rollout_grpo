## Mechanism and contribution

With binary verifiable rewards, a uniform-reward group has zero reward-derived GRPO advantage. A group with at least one correct and one incorrect completion is **mixed**. Mixed groups per generated token measures collection yield. Group size, reward balance, and the prompts that survive selection can all affect learning, so held-out accuracy is a separate outcome. [DeepSeekMath, §4.1](https://arxiv.org/abs/2402.03300)

SARA already uses a Bayesian mixed-group predictor, sequential stopping, and reallocation to fresh prompts. DUET separately evaluates a prompt-dependent token-cost allocator, and Knapsack RL allocates rollouts by expected value and cost. This project tests whether prompt-specific continuation costs improve **the next-chunk choice between a fresh probe and a partially sampled uniform group**, beyond what average costs for the same rollout state can achieve. Both arms use the same empirical mix probabilities. Measuring the value of Bayesian uncertainty would require a separate comparison. [SARA, §§3.2–3.3 and Appendix C.7](https://arxiv.org/html/2607.26253v1) · [DUET, §§3.1 and 4.4](https://arxiv.org/html/2605.08441) · [Knapsack RL](https://proceedings.mlr.press/v306/li26v.html)

## Controller

Generate four completions per action and cap each prompt at 16. Use one frozen rollout policy, decoding configuration, and binary verifier throughout each collection window. Accept and close a mixed group at the end of its chunk. Uniform groups can compete for further chunks until they mix, reach the cap, or the window ends.

**Score.** Rank actions by $\widehat q/\widehat C$, the estimated probability of gaining a mixed group on the next chunk divided by its predicted generated-token cost. For fresh probes, estimate $\widehat q$ from the fraction of calibration prompts that mix in the first four completions. For continuations, estimate the next-chunk mix rate among calibration prompts with the same count (4, 8, or 12) and uniform outcome (all correct or all incorrect). Use the same calibration states to estimate pooled costs. If a continuation stratum has too few prompts, first pool outcomes at the same count, then pool across continuation counts. Set the minimum support on calibration data before opening held-out replay. If even the pooled continuation estimate lacks support, exclude those actions from both arms and report their frequency.

The score values immediate yield. When the fresh probe has positive estimated mix probability, a continuation outranks it when its predicted cost relative to the fresh probe is below its estimated mix probability relative to the fresh probe. Under a $\mathrm{Beta}(1,1)$ prior, four fresh draws mix with probability $3/5$, and four more after $n$ identical outcomes mix with probability $4/(n+5)$. That implies break-even cost ratios of about 74%, 51%, and 39% after 4, 8, and 12 identical rewards. These are reference values. Use empirical rates to see whether continuations can compete in the pilot. [SARA, Proposition 1](https://arxiv.org/html/2607.26253v1)

**Matched pair.** Both arms use the same probabilities, pooled mean fresh-probe cost, and eligibility rules. The pooled-cost arm uses the mean next-chunk token count for the relevant continuation stratum. The token-cost arm's pilot estimator is four times the mean generated length of the prompt's completions observed so far, with the same pooled cost as a fallback if lengths are unavailable. Fit the shared calibration tables on the initial checkpoint and keep them and the estimator rule fixed for the primary comparison. The per-prompt length estimate updates only when another chunk returns. Assess drift separately at a prespecified later checkpoint if the pilot budget allows. Treat material calibration drift as a limit on transfer, and evaluate any recalibration rule as a separate comparison on fresh replay data.

**Dispatch.** For a dispatch width of $W$, offer up to $W$ fresh prompts from the head of the shared stream each round alongside all eligible continuations. Fill the dispatch with the highest-scoring feasible actions, one chunk per prompt, breaking ties by stream order. An unscheduled fresh prompt keeps its place in the stream and an unscheduled continuation remains eligible in the current window. Reserve the worst-case token cost under both the window and run caps, shrink the dispatch as needed, and debit actual generated tokens, including discards. Close the window when no action fits or remains and discard unfinished uniform groups in the mixed-group arms. Start the next window with a new rollout snapshot and carry forward the unprobed stream position. After closing a window, end the run if the stream is exhausted or the remaining run budget cannot admit a full fresh action. Eligible continuations can still run in the final window after the last fresh prompt is probed.

**Training update.** Use one optimizer step per nonempty window, including windows with a single retained group. Skip empty windows and still charge their generation. Center and scale rewards within each finalized group using the population standard deviation plus a fixed stabilizer, with zero advantages for uniform groups. Average the masked loss within each completion, then across completions within a prompt and across prompts in the window. Preserve that weighting across microbatches. The pilot defaults are symmetric ratio clipping at 0.2, a $10^{-6}$ advantage stabilizer, and zero KL penalty. With one step from the rollout snapshot, the ratios start at one and clipping should be inactive when the rollout and training log probabilities match. Freeze optimizer settings after the smoke test and use the same constant learning rate across arms. Check that the variable-group path matches the fixed-size loss and update on identical fixed-size data. Log the accepted group count and optimized tokens per update so changes in update frequency and batch size can be interpreted.

- **Prediction checks.** Compare predicted next-chunk lengths with actual lengths and the pooled-cost benchmark. Check empirical mix rates by stage, uniform outcome, and predicted-cost range. The score assumes that the shared mix rate is a useful approximation even when estimated costs differ within a state. Set calibration tolerances and minimum bin sizes before opening held-out replay. If mix rates vary materially across cost ranges or the estimator fails its length check, pause before online runs and assess any revision on a fresh split.
- **Decision checks.** Score the same feasible actions with both arms on replay states from each. Report how often both action types are available, how often dispatches differ, and how often each arm behaves like fresh-only. Separate fresh-to-continuation switches, the reverse, and substitutions between continuations. Compare immediate yield and cost for switched actions and report whole-run yield separately to capture effects on later decisions.
- **Prompt coverage.** Compare which prompts each arm accepts or leaves uniform by all-fail versus all-correct state, observed length, and realized solve rate across the 16 cached completions. Use the latter as a replay diagnostic only. Report the share of abandoned uniform groups that would have become mixed within 16 completions. This makes it possible to see whether higher collection yield comes with fewer long prompts or fewer difficult prompts that eventually produce a correct response.
- **Budget check.** Exercise the actual reservation rule on pilot lengths. With maximum completion length $L_{\max}$, the last four-rollout action requires $4L_{\max}$ remaining even if it would use less. A full fixed-8 action requires $8L_{\max}$. Verify the per-update cap can admit a full action and that each arm can reach the planned run-budget tolerance without changing decoding or group size.
- **Go/no-go.** Before opening held-out replay, freeze the minimum whole-run yield gain over the pooled-cost arm and the best simple control, along with the prediction and budget tolerances. Advance if the candidate changes dispatches, clears the yield margin, passes the checks, and fits the online GPU budget. Evaluate any revision made after opening held-out replay on a fresh split.
